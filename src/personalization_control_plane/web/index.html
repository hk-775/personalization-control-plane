One inspectable loop

From policy intent to accountable outcomes.

Operators define what “better” means, bound the blast radius, observe outcomes, and retain the power to stop. The service makes each decision reproducible instead of hiding it behind a black box.

01 / DEFINE

Version recommendation policy

Declare an exact purpose, allowed normalized features, objective weights, exploration rate, and candidate safety floor.

02 / PROVE

Review risk before launch

Validate cohort size, policy scope, traffic limits, fairness thresholds, and whether a named human must approve.

03 / SERVE

Rank with deterministic evidence

Allocate traffic stably, score multiple bounded objectives, exclude unsafe candidates, and return factor-level explanations.

04 / RESPOND

Measure, roll back, audit

Link exposures to outcomes, suppress undersized metrics, trigger rollback on breaches, and verify the audit hash chain.

Non-negotiable boundaries

Safety is behavior, not a slide.

The demo refuses unsafe inputs and unsafe state transitions. These controls are exercised by API tests and visible in the operator experience.

C

Consent before personalization

Ranking requests without affirmative consent return a refusal—never a silently personalized result.

P

Exact purpose limitation

Policy, cohort, exposure, and outcome purposes must match. Data cannot drift into a new optimization goal.

∅

No sensitive scoring inputs

Protected and sensitive attribute keys are rejected recursively from context, metadata, and feature contracts.

50

Minimum cohort floor

Small cohorts cannot launch experiments, and their metric values are suppressed from API responses.

H

Human approval at risk

High traffic, high exploration, or large objective shifts create a pending approval instead of launching.

↶

Rollback and global stop

Guardrail failures roll back live experiments. The kill switch pauses all experiments and serves approved baselines.

Explicit demo limitations

  • Not a claim of production fairness or regulatory compliance.
  • No causal inference, learned model, or online feature store.
  • SQLite and a single process are evaluation defaults.
  • Authentication and organizational RBAC are deployment responsibilities.
  • Opaque aggregate group keys demonstrate parity mechanics only.
  • Production rollout still requires domain review and impact assessment.
